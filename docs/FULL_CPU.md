# Первый полный CPU-прогон

Статус: подготовлен, полное обучение не запускалось.

| Шаг | Зачем | Настройки |
|---|---|---|
| Обучить контроль без истории | Получить полный baseline перед DIN | Все 3 151 208 train-лент, одна эпоха, seed=42, CPU |
| Проверить val | Измерить локальную NDCG | Вся val, не входит в обучение |
| Предсказать test | Подготовить файл для самостоятельной отправки | Все кандидаты test, без меток |
| Проверить файл | Исключить пропуски, дубли и некорректные scores | Точное сравнение с sample_submission |

Используем контроль B02 (93 097 параметров), а не признанную улучшением модель с историей: устойчивый выигрыш B02 не подтверждён. Это масштабирование базового решения, не новая проверка B02. train+val не объединяем.

## Запуск на Mac

Из корня проекта, с установленным окружением baseline/.venv:

```bash
nohup caffeinate -i bash scripts/run_full_cpu.sh >> runs/full-cpu.log 2>&1 < /dev/null &
```

Просмотр прогресса:

```bash
tail -f runs/full-cpu.log
```

Control+C при просмотре останавливает только tail. Для самого обучения требуется остановить процесс Python. Крышку оставить открытой, подключить питание. Команда не отправляет данные на сервис.

Скрипт отказывается перезаписывать существующую папку runs/full-cpu-control-seed42-01/. Ошибка любого шага прекращает цепочку. Строка [finished] Submission file в конце подтверждает выполнение всех четырёх шагов, включая проверку файла.

## Результаты

В runs/full-cpu-control-seed42-01/:

- model.pt — модель после оценки val (одна эпоха).
- model_latest.pt — промежуточные веса каждые 10 000 батчей, затем после эпохи. Во временных весах есть step и completed_epoch. Это страховка для оценки/предсказания, **не полноценное продолжение обучения**: optimizer/RNG для resume не сохраняются.
- history.json, config.json, metrics.json, manifest.json — метрики, параметры, исходники и замеры ресурсов.
- validation/metrics.json и predictions_val.parquet — отдельная проверка после загрузки весов.
- test.parquet — файл для отправки, использовать только после успешного последнего шага validate.

Промежуточный model_latest.pt до завершения эпохи нельзя выдавать за обучение на всех данных. После первой полной эпохи решаем о продолжении по измеренным времени и качеству, а не запускаем автоматически ещё четыре.

## Время и память

Полный train в 63 раза больше 50k. По предыдущим прогонам грубый ориентир одной эпохи — около 10–12 часов; новые IO-оптимизации могут его изменить. Это экстраполяция, не измерение полного запуска. Пять эпох могут занять около двух суток.

Используем потоковое чтение по одному Parquet-файлу. В контроле не читаем и не усредняем ненужную историю. После файла даём ОС совет освобождать отображённые страницы memmap (если поддерживается); это не жёсткая гарантия памяти и ОС может отказать. Не загружаем все int8-эмбеддинги в float32.

При test-предсказании сохраняем scores батчами во временные файлы и объединяем в один Parquet, затем временные части удаляются. Итоговый валидатор читает все ключи в память; полный test ранее успешно проверялся на этом Mac.

Проверка исполнения: синтетический полный цикл train→reload val→test, промежуточные веса, пропуски векторов/категорий, пропуск истории и освобождение страниц. На 200 реальных лентах оптимизированный контроль дал **точно те же предсказания**, что и исходный контроль B02. Проверка на 2000 train + всей val заняла 28.82 с с пиком RSS 2.741 GiB; это не гарантия для полного train. 22 теста прошли. Подробные замеры 2k сохранены локально в runs/full-preflight-control-2k/manifest.json. Полный train не запускался.

baseline/ и общий расчёт метрики не менялись. Команды CPU/MPS и исторические проверки B02 остаются доступными; новые опции IO по умолчанию выключены и не подменяют выполненные B02-эксперименты.
