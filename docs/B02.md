## Архитектура и признаки

Сохраняем Transformer по кандидатам из baseline, добавляем средний вектор истории к пользовательскому входу. Это минимальная адаптация исходной модели; отдельный MLP вместо Transformer не проверяется, чтобы не смешивать две архитектурные гипотезы.

Каждый доступный ненулевой int8-вектор события сначала переводится в float32 и L2-нормализуется. Затем считаем обычное среднее (повторные события учитываются повторно). Итоговое среднее дополнительно не нормализуется. Все типы событий имеют одинаковый вес; время, категории истории, источники и target не используются в этом агрегате.

Исторический вход: 128 компонент среднего + флаг отсутствия пригодных векторов. Пустая история, все отсутствующие или нулевые векторы дают нулевое среднее и флаг 1. Индекс -1 не читается, другие невалидные индексы вызывают ошибку. Непригодные векторы исключены из знаменателя.

Пользовательский Linear меняется с 128→64 на 257→64. Кандидаты, два encoder-слоя и scoring-слой остаются прежними. В обеих версиях 93 097 параметров (исходная сеть: 84 841). Контроль обнуляет все 129 исторических входов, включая флаг. Начальные веса, seed, батчи, AdamW/BCE и правило выбора эпохи одинаковы. Равенство числа параметров структурное: веса нулевой ветви контроля не получают полезного сигнала.

## Загрузка

HistoryFeeds читает один Parquet-shard за раз; индексы истории не материализуются для всего train. Эмбеддинги — read-only int8 memmap конкретного split. Среднее считается для одной ленты. Целые ленты сохраняются при батчинге. Для воспроизводимости требуется num_workers=0.

Словарь категорий строится только по выбранному train, категории 0/неизвестные имеют код 0. Лимит первых лент фиксируется до перемешивания. На каждой эпохе переставляем train-файлы и ленты внутри файлов локальным RNG seed+epoch. Поэтому загрузчик отличается от глобального shuffle исходного baseline: сравнение с B01 напрямую некорректно. Контроль и история B02 используют один новый загрузчик.

При оценке порядок файлов фиксирован; прогнозы записываются по ключам из батча. Padding исключён из BCE и метрики, маскирован в attention. Validation не меняет training RNG.

## Проверки и реальные малые запуски

- 17 тестов: прежние проверки и новые проверки истории/загрузки/сети.
- Контроль и история: по 200 train, 100 val, две эпохи, seed=42. Обе версии успешно завершились. Первый запуск 5.95 с, второй 1.23 с; времена не сравниваем как скорость архитектур, прогрев и кэш различаются. Пик RSS обоих процессов около 1.16 GiB.
- Профиль истории: 2000 train, 100 val, одна эпоха: 28.62 с, пик RSS 4.603 GiB.
- Сохранённый checkpoint истории восстановлен отдельным процессом: оценки на тех же 100 val совпали точно, Logloss/NDCG совпали.
- Отдельно выполнено предсказание маленькой модели на всей val: 14 423 ленты / 1 389 971 кандидат, 16.62 с, пик RSS 0.567 GiB. Проверены точные ключи, уникальность и конечность float32 scores. NDCG=0.30562 — только показатель smoke-модели, не доказательство B02; у контроля пока нет соответствующей полной проверки.
- Средние и logits вычисляются без переполнения int8. Синтетически проверены неизвестные категории, test без target, перестановки событий/кандидатов, неодинаковые ленты, маски, конечные градиенты и одинаковые параметры двух моделей.

Малые значения метрик сохранены в [preflight.json](../experiments/B02/preflight.json), но по ним не выбираем победителя.

## Файлы и воспроизведение

- src/neuroforge/models/neural/history_mean.py — загрузчик, среднее, collate и расширение сети.
- scripts/train_b02.py — CPU-обучение, прогресс, лучший checkpoint по полной NDCG на переданной val, logits, история/конфиг/манифест/отчёт.
- scripts/evaluate_b02.py — отдельная загрузка весов и оценка val.
- tests/test_history_mean.py — новые проверки.
- configs/B02_cpu_smoke.json и B02_cpu_profile.json — выполненные малые прогоны.
- configs/B02_cpu_50k.json — следующий, НЕ выполненный запуск: 50k train, вся val, пять эпох, seed=42.
- runs/B02-control-smoke-01/, B02-history-smoke-01/, B02-history-profile-2k-01/, B02-preflight/ — локальные веса, прогнозы, манифесты, журналы.

```bash
PYTHONPATH=src uv run --project baseline python -m unittest discover -s tests -v
uv run --project baseline python scripts/train_b02.py --data data/competition --variant control --output runs/B02-control-smoke-repeat
uv run --project baseline python scripts/train_b02.py --data data/competition --variant history --output runs/B02-history-smoke-repeat
uv run --project baseline python scripts/evaluate_b02.py --data data/competition --model runs/B02-history-smoke-repeat/model.pt --max-feeds 0 --threads 1 --output runs/B02-history-smoke-repeat/val-full
```

## Состояние после содержательных экспериментов

Проведены четыре запуска на 50k: контроль/история для seed=42 и 123, каждый по пять эпох с полной val. Устойчивого прироста не установлено; см. B02_RESULTS.md. Обучение на полном train не проводилось.

Защита --allow-large остаётся для >2000 train или train_feeds=0. Замеры на 50k не гарантируют память/время для 3.15 млн лент. Следующая самостоятельная гипотеза — B03 (внимание к истории под кандидата), она пока не запускалась.

Полную val использовали по решению пользователя, отдельного нетронутого контроля нет. Источники baseline/, общая метрика и общий PROTOCOL.md не менялись. Вклад в ансамбль и сервис не измерен.
