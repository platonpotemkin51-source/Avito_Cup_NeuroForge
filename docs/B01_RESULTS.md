# B01: выбор эпохи по NDCG — исторический итог

Одинаковая траектория обучения исходной сети: minimum Logloss против maximum full NDCG. Train50000,5 эпох, два seed. Эпоха выбиралась на первых 100 val-лентах; ниже пересчёт всей val14423 ленты.

| Seed | Logloss-selected NDCG | NDCG-selected NDCG | Разница |
|---|---:|---:|---:|
| 42 | 0.33342171 | 0.33425457 | +0.00083286 |
| 123 | 0.32920555 | 0.32825941 | -0.00094614 |

Устойчивого выигрыша исходной B01 на маленькой selection выборке не подтвердили. Не считать её доказанным повышением метрики. Сохранили полезный общий принцип: готовая B02 сеть выбирает checkpoint по целевой метрике NDCG на выбранной val целиком, без sigmoid/округления logits.

Подробные числа и аудиты — experiments/B01/. Старые модели/прогнозы/launcher удалены при согласованной очистке; исторические paths в audit JSON не означают существующие файлы. Не нужно воспроизводить старую CPU абляцию для обучения готовой сети.

Логика B01 остаётся в checkpoint_selection.py как пример для исходного baseline и в требованиях к циклу обучения капитана: maximum full NDCG, не minimum Logloss. Капитанский ИИ интегрирует её в свой trainer для SignalRanker. [Передача капитану](CAPTAIN_AI_HANDOFF.md); [итог B02](B02_RESULTS.md).
