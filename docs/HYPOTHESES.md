# Гипотезы команды

Все пункты ниже — проверяемые идеи, прирост не гарантирован. Основной критерий — полный NDCG и вклад в ансамбль на позднем контроле. Изменения фиксируем отдельно, контроль и состав выборки не меняем одновременно с моделью.

## Ветка A

| ID | Идея | Эксперимент |
|---|---|---|
| A01 | Выбор по полному NDCG | Сравнить исходный выбор по @30 с полным NDCG при одинаковом обучении. |
| A02 | Частоты и окна истории | Добавить категории/типы/источники в окнах 8,32,128,256; проверять окна и блоки отдельно. |
| A03 | Сходства с историей | Max, mean и top-k cosine кандидата к прошлым объявлениям; отдельные группы событий. |
| A04 | Конкуренция внутри ленты | Ранги, процентили и отклонения f1–f5 и сходств среди кандидатов. |
| A05 | Функции потерь и регуляризация | YetiRank и допустимые на выбранном устройстве альтернативы; сравнить веса лент, глубину и регуляризацию. |
| A06 | Временные и ID-агрегаты | Сглаженные статистики только из прошлых меток, неизвестные ID, свежие окна train; оценить на новых объектах. |
| A07 | Коллаборативный сигнал | Item2Vec/факторизация из train-историй как дополнительный скор заданного кандидата; проверить вклад сверх A03. |

## Ветка B

| ID | Идея | Эксперимент |
|---|---|---|
| B01 | Правильный checkpoint | Сравнить выбор по Logloss и полному NDCG; сохранять logits для оценки. |
| B02 | Агрегированная история | MLP со средними/взвешенными векторами истории; отделить эффект истории от увеличения размера. |
| B03 | DIN | Внимание к истории зависит от кандидата; сравнить с B02 при близком бюджете. |
| B04 | Последовательность | Трансформер истории с позициями/типами/источниками; убрать позиции в контрольном эксперименте. |
| B05 | Контекст кандидатов | Добавить взаимодействия кандидатов после истории; проверить перестановочную согласованность. |
| B06 | Несколько интересов | 2/4/8 представлений пользователя; сравнить с одним при сопоставимой ёмкости. |
| B07 | Потери и предобучение | Раздельно проверить listwise/pairwise, равный вес лент и предобучение на train-истории; затем совместить подтверждённое. |

Состояние участника2: B01 и B02 завершены. В B02 принят top3 similarity, см. [итог](B02_RESULTS.md). Ближайший архитектурный этап — B03; полное обучение готовой модели передаётся капитану по [инструкции](CAPTAIN_AI_HANDOFF.md).

## Ветка C

| ID | Идея | Эксперимент |
|---|---|---|
| C01 | Временная устойчивость | Зафиксировать раннюю val и поздний контроль, измерить перенос по дням и новым ID; это проверка выбора, не новая модель. |
| C02 | Простой ансамбль | Среднее scores после согласования масштаба, стандартизация внутри ленты, среднее рангов; веса на development. |
| C03 | Коррекция позиции | Отдельный компонент pos при обучении и ограниченные веса; не считать обратный CTR истинной propensity. |
| C04 | Свежесть обучения | Сравнить всё train, свежие окна и временные веса на нескольких будущих блоках. |
| C05 | Разнообразие моделей | Проверить несколько seed и разных семейств; удалять по одной модели из ансамбля для оценки вклада. |
| C06 | Обучаемое объединение | Stacking только на отложенных прогнозах с отдельной будущей проверкой; сравнить с C02. |
| C07 | Переобучение перед финалом | Имитировать добавление последнего доступного периода, фиксировать число эпох; затем решить о train+val. |

Для каждой: записать контроль, ожидаемый механизм, ресурсный бюджет, основной результат и срезы. Небольшие приросты повторить. Слабую отдельно модель проверить в ансамбле. Принятие: корректность → перенос по времени → повторяемость → добавочный результат. Отрицательный результат сохранить. Большие модели после малого smoke проверять на достаточном объёме, не отбрасывать по одному малому прогону.
