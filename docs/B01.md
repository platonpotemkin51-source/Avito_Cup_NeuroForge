# B01 — выбор эпохи по NDCG

**Статус: проверена, текущий вариант закрыт без принятия.** На двух seed устойчивого прироста нет. [Отчёт](B01_RESULTS.md) содержит результаты, ограничения и материалы для передачи капитану.

## Что меняется

Используем исходные архитектуру, BCE, AdamW и загрузчик организаторов без изменения baseline/. После каждой эпохи считаем полный NDCG на float32 logits. В одном обучении сохраняем две лучшие версии: по минимальному Logloss и максимальному NDCG. При равенстве остаётся ранняя эпоха.

Дополнительная проверка сохраняет состояние CPU RNG: она не меняет последующие батчи и dropout. История пользователя в модели пока не используется.

## Запуск

Из корня проекта, после установки окружения по README:

```bash
uv run --project baseline python scripts/train_b01.py --config configs/B01_cpu_50k.json --data data/competition --output runs/B01-repeat-seed42
uv run --project baseline python scripts/train_b01.py --config configs/B01_cpu_50k_seed123.json --data data/competition --output runs/B01-repeat-seed123
```

Запускать последовательно. Оба конфига: 50 000 train, первые 100 val, 5 эпох, batch 2, CPU, четыре потока. Они отличаются только seed. Для проверки кода есть configs/B01_cpu_smoke.json: 200 train, 100 val, пять эпох.

Исходный одноэпоховый smoke и CPU/MPS-проверка также доступны через scripts/run_baseline.py и configs/neural_smoke.json / neural_mps_smoke.json. Они проверяют запуск, не пользу B01.

## Выход

| Файл | Содержимое |
|---|---|
| model.pt | Лучшая эпоха по Logloss |
| model_ndcg.pt | Лучшая эпоха по NDCG |
| predictions_val_logloss.parquet / predictions_val_ndcg.parquet | Логиты на выборке выбора эпохи с ключами feed_id/item_id |
| run.json / metrics.json | История эпох / сравнение критериев |
| config.json / manifest.json / report.md | Настройки, окружение, исходники, время, память и ограничения |

Оценка полного val и сравнение выполняются scripts/evaluate_neural.py и scripts/compare_b01.py; команды приведены в отчёте. Существующие выходные папки не перезаписываются.

## Ресурсы и проверки

При загрузке выводятся сообщения каждые пять секунд; внутри эпох — число батчей, elapsed, примерная ETA текущего прохода и пиковая RAM процесса. Прогресс не меняет порядок батчей и RNG.

Оба больших прогона заняли около 23 минут, пик RSS процесса около 5 ГБ. Это замер для 50k, не гарантия для полного train. Полное обучение не выполнялось.

14 тестов прошли. Отдельно проверены синтетический сквозной запуск и совпадение полной NDCG четырёх моделей с CatBoost. Ансамбль и качество на сервисе не измерены.
