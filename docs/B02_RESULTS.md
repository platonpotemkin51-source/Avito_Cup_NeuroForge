# B02 закрыта: история и признаки сходства

**Оставляем готовое сходство пользователя с объявлением и top3 сходство с недавней историей.** Прирост подтвердился локально на двух seed. Ранги и повторение новой категории не оставляем. Private NDCG и вклад в ансамбль не измерены.

## Рабочая модель

Для каждого кандидата рассчитываются user cosine и среднее трёх максимальных cosine с доступными событиями из первых 32 позиций истории. Если событий меньше трёх, используются имеющиеся; при пустой истории сигнал 0. Число 32 означает порядок событий, а не дни. Int8 векторы переводятся в float32 до арифметики, -1 и нулевые векторы исключаются из агрегирования.

User token: user128 + средняя recent32 история 128 + missing flag. Кандидат: f1–f5, item128, missing flag, category embedding8, четыре скалярных слота. Два заняты полезными сходствами, два остаются нулями для совместимости с измеренными весами. Transformer width64/4 головы/2 слоя/dropout0.1;93353 параметра. Позиции кандидатов не используются. Top3 — вручную рассчитанный кандидатозависимый признак, не DIN. Словарь категорий только train, неизвестные 0.

## Исследование данных перед последними запусками

13 label-free сигналов изучены на 50000 train-лентах/3896275 кандидатах. По SHA256(user_id) выделены exploration35555 и check14445 лент с непересекающимися пользователями; это не временной контроль. Val/test не использовались в этом исследовании. На check AUC среднего recent cosine0.592615, top3 cosine0.608584. Это различение выбранных/невыбранных объявлений внутри ленты, не результат нейросети. Находка затем проверена отдельным контролируемым обучением. Полные агрегированные результаты — experiments/B02/data_study.json.

## Корректность, ограничения и ресурсы

- Для всех 8 моделей независимый CatBoost пересчёт NDCG совпал с отчётом (<1e-10). Проверены точное покрытие/уникальность ключей, конечность float32,10 эпох, правильность лучшего checkpoint, совпадение config/source/cache hashes и числа параметров. Полный аудит — experiments/B02/final_audit.json.
- Val многократно использовалась для checkpoint selection и оценки. Интервалы условны на выбранные модели, без поправки на весь исторический поиск. Позднего независимого контроля нет; Private-прирост не подтверждён.
- Train50000 — фиксированный префикс около 1.6% полного train, не репрезентативная случайная выборка. Полный train не обучался. Разницу нового контроля со старыми опытами не приписываем одному признаку: менялись бюджет, batch и ёмкость.
- Основной выигрыш top3 — на длинной истории. Для 1–32 событий delta-0.00115/-0.00162 (873 ленты); на пустой истории направление менялось между seed. Это диагностика, не основание подбирать routing на знакомой val.
- 8 финальных моделей суммарно 144.88 минут. Первый запуск упал с MPS OOM. После фиксированного padding и очистки cache все 8 завершились; максимум sampled driver allocation до/после очистки 1.66/0.62GiB — не измеренный пик всей RAM. Время, host RAM и GPU snapshots каждого опыта сохранены в audit JSON.
- Фактический source commit обучения 4d0cdd5 плюс hashes dirty tree сохранены без подмены будущим commit доставки. Старые paths в evidence — исторические идентификаторы, не обещание наличия файлов. Не все удалённые отрицательные trials теперь можно повторить без извлечения старого кода.

## Очистка и совместимость

Удалены отвергнутые modes/builders/launcher/configs/tests, неудачные прогоны, промежуточные веса, expanded caches и дубли отчётов. Около 6GiB освобождено; исходные data/ и baseline/ сохранены. Оставлены две лучшие model.pt и val-прогнозы в runs/B02-final-02/top3-s42 и top3-s123, принятые парные сравнения, журналы победителей и аудит. В Git данных и весов нет.

Код расчёта признаков сокращён до трёх: user cosine, mean recent cosine (контроль), top3 recent cosine. Старые 93353-параметровые checkpoint совместимы: на 64 реальных val-лентах/5015 кандидатах CPU scores до/после очистки совпали точно (max difference0). Это проверка совместимости, не новый полный замер качества.

Сохранены только блоки модели/признаков/порционного чтения и спецификация configs/B02_top3.json. Нового trainer/CUDA launcher в пакете нет по прямому указанию участника: принимающий ИИ сам включает B01 selection и принятый B02 в свой код. Для полного train использовать raw shards/int8 memmap без expanded float cache на~170GB. Модель, маски, градиенты, загрузка state_dict и label-free признаки проверены. CUDA/NVIDIA/Windows execution автором не проверены.
